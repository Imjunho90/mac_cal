# Mini NPU Simulator

## 1. 실행 방법

프로그램은 Python 3.8 이상의 환경에서 실행할 수 있으며 NumPy, pandas 등의 외부 라이브러리는 사용하지 않는다.

python main.py

프로그램을 실행하면 다음 두 가지 모드 중 하나를 선택할 수 있다.

* 1. 사용자 입력 (3x3) : 사용자가 3×3 필터 A, B와 3×3 패턴을 직접 입력하여 각 필터의 MAC 점수와 최종 판정 결과를 확인한다.
* 2. data.json 분석 : data.json에 저장된 5×5, 13×13, 25×25 필터와 패턴을 불러와 각 테스트 케이스를 일괄 분석한다.

data.json 파일은 main.py와 같은 경로에 위치시킨다.

## 2. 구현 요약

### 2.1 라벨 정규화

JSON 데이터에서는 같은 의미의 라벨이 서로 다른 문자열로 표현될 수 있다.

본 프로그램에서는 내부적으로 Cross와 X 두 가지 표준 라벨만 사용하도록 정규화한다.

* + → Cross
* cross → Cross
* x → X

이를 위해 다음과 같이 normalize_label() 함수를 별도로 구현하였다.

def normalize_label(label):
    if label == '+' or str(label).lower() == 'cross':
        return 'Cross'
    if str(label).lower() == 'x':
        return 'X'
    return None

라벨 정규화 기능을 별도의 함수로 분리한 이유는 유지보수성과 확장성을 높이기 위해서이다.

필터의 라벨과 expected 라벨을 사용하는 여러 위치에서 각각 정규화 코드를 작성하면 같은 코드가 반복되며, 라벨 정책이 변경될 경우 여러 부분을 동시에 수정해야 한다.

반면 normalize_label() 함수에서 라벨 변환 규칙을 한 곳에서 관리하면 수정이 필요한 경우 해당 함수만 변경하면 된다.

또한 향후 새로운 라벨 표현 방식이 추가되더라도 normalize_label() 함수에 규칙을 추가하여 프로그램 전체에 동일하게 적용할 수 있다.

따라서 라벨 정규화 기능을 하나의 함수로 분리함으로써 코드의 중복을 줄이고 유지보수성과 확장성을 높였다.

⸻

### 2.2 MAC 연산

MAC(Multiply-Accumulate) 연산은 입력 패턴과 필터의 동일한 위치에 있는 값을 서로 곱하고, 그 결과를 모두 누적하여 하나의 점수를 계산하는 방식이다.

본 프로그램에서는 NumPy 등의 외부 라이브러리를 사용하지 않고 이중 반복문을 이용하여 직접 MAC 연산을 구현하였다.

for i in range(len(pattern)):
    for j in range(len(pattern[i])):
        score += pattern[i][j] * filters[i][j]

Cross 필터와 X 필터에 대해 각각 MAC 점수를 계산하고 두 점수를 비교하여 최종 패턴을 판정한다.

MAC 점수의 의미

본 시뮬레이터에서 MAC 점수는 입력 패턴이 해당 필터의 특징과 얼마나 잘 일치하는지를 판단하기 위한 값으로 사용한다.

입력과 필터의 동일한 위치에 큰 값들이 함께 존재할수록 곱셈 결과가 커지고, 이러한 결과를 모두 누적한 MAC 점수 역시 증가한다.

따라서 본 프로그램에서는 MAC 점수가 클수록 입력 패턴과 해당 필터의 유사성이 높다고 판단한다.

Cross 필터의 점수가 X 필터보다 높으면 Cross, X 필터의 점수가 Cross 필터보다 높으면 X로 판정한다.

단, 두 점수의 차이가 매우 작은 경우에는 명확하게 어느 필터의 유사도가 더 높다고 판단하기 어렵기 때문에 epsilon 정책을 이용하여 UNDECIDED로 처리한다.

⸻

### 2.3 동점 처리 정책

Python에서 실수를 계산할 때 일부 값은 이진 부동소수점으로 정확하게 표현되지 않아 매우 작은 오차가 발생할 수 있다.

따라서 두 MAC 점수를 단순하게 == 연산자로 비교하면 수학적으로 동일하다고 볼 수 있는 값도 서로 다른 값으로 판단될 가능성이 있다.

본 프로그램에서는 이러한 문제를 방지하기 위해 epsilon 값을 다음과 같이 설정하였다.

eps = 1e-9

두 점수의 차이가 다음 조건을 만족하면 실질적으로 동일한 점수라고 판단한다.

abs(score_a - score_b) < eps

조건을 만족하는 경우 최종 판정을 UNDECIDED로 처리한다.

⸻

### 2.4 모드별 동점 처리 정책

Mode 1과 Mode 2 모두 동일한 epsilon 정책을 사용한다.

즉,

abs(score_a - score_b) < 1e-9

이면 두 점수의 차이를 의미 있는 차이로 보지 않고 UNDECIDED로 판정한다.

하지만 두 모드의 목적이 서로 다르기 때문에 UNDECIDED 이후의 처리 방식에는 차이가 있다.

Mode 1

Mode 1은 사용자가 직접 입력한 하나의 패턴이 필터 A와 B 중 어느 쪽에 더 가까운지를 확인하는 기능이다.

Mode 1에는 정답을 의미하는 expected 값이 존재하지 않는다.

따라서 두 MAC 점수가 epsilon 범위 내에서 동일한 경우 A 또는 B 중 하나를 강제로 선택하지 않고 사용자에게 다음과 같이 판정 불가 상태를 알려준다.

판정: 판정불가(|A-B| < 1e-9)

Mode 2

Mode 2는 data.json의 각 테스트 케이스에 존재하는 expected 라벨과 프로그램의 판정 결과를 비교하는 테스트 기능이다.

따라서 MAC 점수 차이가 epsilon보다 작으면 먼저 UNDECIDED로 판정한다.

하지만 expected 값은 Cross 또는 X이므로 UNDECIDED는 expected와 일치하지 않는다.

따라서 해당 테스트 케이스는 최종적으로 FAIL 처리한다.

즉, 두 모드의 동점 판단 기준은 동일하지만 Mode 1은 판정 결과만 제공하고, Mode 2는 expected와 비교하여 테스트 성공 여부까지 평가하기 때문에 최종 처리 방식에 차이가 있다.

### 3.2 FAIL 케이스 원인 분석

data.json 분석 결과 총 6개의 테스트 케이스 중 3개가 PASS, 3개가 FAIL로 판정되었다.

실패한 테스트는 size_5_1, size_13_2, size_25_1이며 세 케이스 모두 두 필터의 MAC 점수 차이가 epsilon보다 작아 UNDECIDED로 판정되었다.

size_5_1은 Cross 점수가 0.9, X 점수가 0.8999999999999999로 계산되었다. 두 값에는 표현상의 차이가 있지만 실제 차이는 epsilon보다 작기 때문에 동점으로 처리하였다.

size_13_2는 Cross 점수가 7.499999999999997, X 점수가 7.5로 계산되었으며 마찬가지로 두 값의 차이가 epsilon 범위 내에 있기 때문에 UNDECIDED로 처리하였다.

size_25_1도 Cross 점수가 4.9, X 점수가 4.899999999999999로 계산되었으며 epsilon 정책에 따라 동점으로 처리하였다.

이와 같은 미세한 차이는 컴퓨터가 일부 실수를 이진 부동소수점 방식으로 정확하게 표현하지 못하면서 발생할 수 있다.

만약 epsilon 정책 없이 단순하게 두 값의 크기만 비교한다면 아주 작은 부동소수점 오차 때문에 실제로는 거의 동일한 점수가 Cross 또는 X로 잘못 판정될 수 있다.

본 프로그램에서는 이러한 문제를 방지하기 위해 abs(score_a - score_b) < 1e-9 조건을 적용하였다.

세 실패 케이스의 expected 값은 각각 X, Cross, X였지만 실제 판정 결과는 UNDECIDED였기 때문에 expected와 일치하지 않아 FAIL 처리되었다.

반면 나머지 세 테스트 케이스는 두 필터의 MAC 점수 차이가 명확했으며, 더 높은 MAC 점수를 가진 필터의 라벨과 expected 값이 일치하여 PASS 처리되었다.

### 3.3 성능 분석

MAC 연산을 크기별로 10회 반복하여 평균 시간을 측정한 결과는 다음과 같다.

크기	평균 시간(ms)	연산 횟수(N²)
3×3	0.002	9
5×5	0.003	25
13×13	0.015	169
25×25	0.053	625

MAC 연산에서는 N×N 패턴의 모든 위치를 한 번씩 순회하면서 입력 패턴과 필터의 값을 곱하고 결과를 누적한다.

따라서 N×N 크기의 입력에서는 총 N²개의 위치에 대해 MAC 연산을 수행해야 한다.

실제 연산 횟수도 크기가 증가하면서 9 → 25 → 169 → 625회로 증가하였다.

측정된 평균 시간 역시 0.002ms → 0.003ms → 0.015ms → 0.053ms로 전반적으로 증가하는 모습을 확인할 수 있었다.

따라서 현재 구현된 MAC 함수의 시간 복잡도는 **O(N²)**이다.

단, 실제 측정 시간은 Python 인터프리터의 실행 오버헤드와 운영체제의 프로세스 스케줄링, CPU 상태 등의 영향을 받을 수 있기 때문에 연산 횟수 N²에 정확하게 비례하지는 않을 수 있다.

⸻

### 3.4 대규모 입력에서의 예상 병목과 최적화

현재 MAC 연산의 시간 복잡도는 O(N²)이므로 N이 증가하면 처리해야 하는 데이터의 수도 빠르게 증가한다.

예를 들어 25×25 크기에서는 625개의 위치를 처리하지만, 1000×1000 크기의 입력에서는 한 번의 MAC 연산에만 총 1,000,000개의 위치를 처리해야 한다.

따라서 입력 크기가 1000×1000 수준으로 증가하면 Python의 이중 반복문에서 수행해야 하는 곱셈과 누적 연산 횟수가 크게 증가하여 연산 시간이 주요 병목이 될 수 있다.

메모리 사용량 역시 증가한다. 현재 프로그램은 패턴과 필터를 Python의 2차원 리스트 형태로 저장하기 때문에 입력 크기가 커질수록 저장해야 하는 원소의 수와 리스트 구조 자체의 메모리 오버헤드가 함께 증가한다.

또한 CPU가 필요한 데이터를 메모리에서 지속적으로 가져와야 하기 때문에 계산량뿐만 아니라 메모리 접근 역시 성능에 영향을 줄 수 있다.

대규모 입력에서는 우선적으로 블로킹(Blocking) 또는 타일링(Tiling) 방식을 고려할 수 있다.

블로킹 또는 타일링은 큰 데이터를 작은 블록 단위로 나누어 처리하는 방식으로, 한 번에 필요한 데이터의 범위를 제한하여 CPU 캐시에 데이터를 재사용할 가능성을 높일 수 있다.

이를 통해 큰 행렬 전체에 반복적으로 접근하는 것보다 메모리 접근 효율을 높일 수 있다.

또한 대규모 데이터에서는 Python 반복문을 하나씩 수행하는 것보다 여러 MAC 연산을 동시에 처리할 수 있는 병렬 연산 구조를 활용하는 것이 중요하다.

따라서 대규모 입력에 대한 우선적인 최적화 방향은 메모리 접근 효율 개선과 MAC 연산의 병렬화라고 볼 수 있다.

### 3.5 CPU와 NPU의 MAC 연산 처리 차이

현재 Mini NPU Simulator는 Python의 이중 반복문을 사용하기 때문에 각 위치의 MAC 연산을 코드상 순차적으로 수행한다.

일반적인 CPU는 프로그램 실행, 조건문, 파일 처리 등 다양한 종류의 작업을 수행하도록 설계된 범용 프로세서이다.

현대 CPU 역시 멀티코어와 SIMD 등의 병렬 처리 기능을 지원하지만, 대규모 신경망에서 반복적으로 발생하는 많은 수의 MAC 연산을 처리할 때는 연산 처리량과 메모리 접근이 병목이 될 수 있다.

반면 NPU(Neural Processing Unit)는 신경망의 행렬 연산과 MAC 연산을 효율적으로 수행하도록 설계된 AI 전용 프로세서이다.

NPU는 다수의 MAC 연산 유닛을 이용하여 여러 곱셈 및 누적 연산을 병렬로 수행할 수 있도록 설계되며, 신경망에서 반복적으로 사용되는 데이터의 이동과 재사용도 효율적으로 처리하는 구조를 사용할 수 있다.

따라서 입력 크기가 커질수록 단순히 MAC 연산의 개수만 중요한 것이 아니라 얼마나 많은 MAC 연산을 동시에 수행할 수 있는지와 연산에 필요한 데이터를 얼마나 효율적으로 공급할 수 있는지가 전체 성능에 큰 영향을 준다.

본 Mini NPU Simulator는 이러한 실제 하드웨어의 병렬 구조를 구현한 것은 아니며, Python을 이용하여 MAC 연산의 기본 원리와 데이터 크기에 따른 연산량 증가를 확인하는 것을 목적으로 한다.

실제 NPU에서는 많은 MAC 연산을 하드웨어 수준에서 병렬화하여 대규모 AI 연산을 보다 높은 처리량으로 수행할 수 있다.
