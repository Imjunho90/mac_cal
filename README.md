

## 결과 리포트


~~~bash
=== Mini NPU Simulator ===

 [모드 선택]
1. 사용자 입력 (3x3)
2. data.json 분석
선택:2

#-----------------
# [1] 필터 로드
#-----------------
✓ size_5 필터 로드 완료 (Cross, X)
✓ size_13 필터 로드 완료 (Cross, X)
✓ size_25 필터 로드 완료 (Cross, X)

#-------------------------------
 [2] 패턴 분석
#-------------------------------
---size_5_1---
Cross 점수0.9
X 점수 0.8999999999999999
판정 UNDECIDED | expected: X | FAIL
---size_5_2---
Cross 점수8.9
X 점수 0.1
판정 Cross | expected: Cross | PASS
---size_13_1---
Cross 점수0.3
X 점수 14.700000000000008
판정 X | expected: X | PASS
---size_13_2---
Cross 점수7.499999999999997
X 점수 7.5
판정 UNDECIDED | expected: Cross | FAIL
---size_25_1---
Cross 점수4.9
X 점수 4.899999999999999
판정 UNDECIDED | expected: X | FAIL
---size_25_2---
Cross 점수52.9
X 점수 0.1
판정 Cross | expected: Cross | PASS

#-------------------------------
 [3] 성능 분석 (평균/10회)
#-------------------------------
크기   평균 시간(ms) 연산 횟수
3x3     0.002ms       9
5x5     0.003ms      25
13x13    0.015ms     169
25x25    0.053ms     625

#---------------------------------------
# [4] 결과 요약
#---------------------------------------
총 테스트: 6개
통과: 3개
실패: 3개

실패 케이스:
-size_5_1: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
-size_13_2: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
-size_25_1: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
~~~
data.json 분석 결과 총 6개의 테스트 케이스 중 3개가 PASS, 3개가 FAIL로 판정되었다.
실패한 케이스는 size_5_1, size_13_2, size_25_1이며 모두 UNDECIDED 판정으로 인해 FAIL 처리되었다.
size_5_1의 Cross 점수는 0.9, X 점수는 0.8999999999999999로 두 값에 미세한 차이가 발생하였다.
size_13_2 역시 Cross 점수가 7.499999999999997, X 점수가 7.5로 미세한 차이가 발생했으며 size_25_1에서도 4.9와 4.899999999999999의 차이가 발생하였다.
이러한 차이는 실수를 이진수로 표현하는 과정에서 발생할 수 있는 부동소수점 오차로 볼 수 있다.
따라서 두 점수를 단순히 == 연산자로 비교하지 않고 abs(score_a - score_b) < 1e-9의 epsilon 비교 정책을 적용하였다.
세 실패 케이스는 점수 차이가 epsilon보다 작았기 때문에 실질적인 동점으로 판단하여 UNDECIDED로 처리되었고, expected 값과 일치하지 않아 FAIL이 되었다.
반면 나머지 3개의 테스트 케이스는 Cross와 X의 점수 차이가 명확했으며, 판정 결과가 expected 라벨과 일치하여 PASS 처리되었다.
성능 분석 결과 연산 횟수는 3×3에서 9회, 5×5에서 25회, 13×13에서 169회, 25×25에서 625회로 증가하였다.
실제 평균 연산 시간도 각각 약 0.002ms, 0.003ms, 0.015ms, 0.053ms로 행렬의 크기가 커질수록 증가하는 경향을 확인하였다.
MAC 연산은 N×N 배열의 모든 위치를 순회하면서 패턴과 필터의 값을 곱하고 누적하기 때문에 총 N²개의 위치를 처리한다.
따라서 본 프로그램에서 구현한 MAC 연산의 시간 복잡도는 O(N²)이며, 측정된 연산 시간의 증가 역시 연산 횟수 증가와 대체로 일치하는 경향을 보였다.
단 실제 측정 시간은 운영체제의 스케줄링이나 Python 실행 환경 등의 영향을 받을 수 있으므로 N²에 정확히 비례하지 않을 수 있다.
